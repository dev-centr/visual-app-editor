## About

![Widget Bench editing a sample Flutter project: widget tree on the left, phone canvas in the middle, properties on the right](docs/modules/ROOT/images/screenshot.png)

Widget Bench is for Flutter developers who want to lay out screens by clicking and dragging without giving up their codebase. It opens an ordinary Flutter project and edits its `.dart` files directly:

- **Your code stays yours.** A visual edit changes only the expression it touches. Comments, state classes, helpers and formatting elsewhere in the file are kept byte-for-byte. Edits that would not parse are refused.
- **Any widget library.** The toolbox is generated by scanning a package's public widget classes and constructor parameters with `package:analyzer`. Material, Cupertino and the core widgets are bundled; manifests for shadcn_ui, forui, fluent_ui and macos_ui are included, and you can add your own.
- **Offline.** No account and no cloud. It reads the Flutter SDK and pub cache on your machine.
- **Two previews.** An instant in-process canvas that renders the page from source, and a *Run* button that starts your real app with hot reload on every save.

Panels: pages, toolbox, widget tree, canvas with phone / tablet / desktop frames, properties, theme, toolkits, and a code view.

## Getting started

### Prerequisites

- The [Flutter SDK](https://docs.flutter.dev/get-started/install) with `flutter` on `PATH` (or `FLUTTER_ROOT` set). Widget Bench reads widget sources from it.

### Install

No public release has shipped yet. Installers are built by CI for every push to `main`; download them from the workflow run's artifacts:

| Platform | Architectures | Package |
| --- | --- | --- |
| Windows | x64, arm64 | `WidgetBench-<version>-windows-<arch>-setup.exe` |
| Linux | x64, arm64 | `.AppImage`, `.deb` |
| macOS | arm64 | `.dmg` (unsigned) |

### Build from source

```sh
git clone https://github.com/dev-centr/widget-bench.git
cd widget-bench
flutter pub get
flutter run -d windows   # or linux / macos
```

Installers: `packaging/windows/build-installer.ps1`, `packaging/linux/build-packages.sh`, `packaging/macos/build-dmg.sh`.

## Usage

1. **Open project** and pick a folder with `pubspec.yaml`, or create the bundled sample project.
2. Choose a page. Click a widget on the canvas or in the tree.
3. Edit values in **Properties**. Values are Dart expressions: `'Hello'`, `24`, `Colors.teal`, `EdgeInsets.all(12)`.
4. Drag widgets from the **Toolbox** onto tree rows, or click to add under the selection. Wrap, reorder and delete from the tree toolbar.
5. **Ctrl+S** saves. **Run** starts the app with `flutter run` and hot reloads on save.

`widget_bench <project-folder>` opens a project from the command line; `widget_bench --version` prints the version.

## Toolkits

A toolkit is an SDL manifest naming a package and the folders to scan:

```sdl
toolkit "forui" {
	name "Forui"
	package "forui"
	import "package:forui/forui.dart"
	library "src/widgets"
	exclude "^_" "Style" "Data$"
	category "Buttons" "FButton"
}
```

Put extra manifests in `<project>/.widget_bench/toolkits/`. Add the package to your project and run `pub get` so it can be found. Details: [toolkit manifests](docs/modules/ROOT/pages/toolkit-manifests.adoc).
