= Publishing the IDE plugins
:page-audience: Developer
:toc:

The VS Code extension 0.1.0 is published on the Visual Studio Marketplace as https://marketplace.visualstudio.com/items?itemName=devcentr.visual-app-editor[devcentr.visual-app-editor] (2026-10-20). The JetBrains Marketplace and Open VSX are not published yet. This page lists what each marketplace requires, so a first release is a checklist rather than a discovery.
It contains no secrets: tokens and keys belong in repository or environment secrets, never in the repository.

Checked against the vendor docs on 2026-10-20:

* https://code.visualstudio.com/api/working-with-extensions/publishing-extension
* https://github.com/microsoft/vscode-vsce (README, trusted publishing)
* https://github.com/microsoft/vsmarketplace/issues/1422 (GitHub Actions + Entra guide; `--oidc` backend status)
* https://github.com/marketplace/actions/azure-login

== Build artifacts

CI builds both plugins on every push and uploads them as workflow artifacts:

[cols="1,2,2"]
|===
| Plugin | Artifact | File

| IntelliJ IDEA / Android Studio | `visual-app-editor-intellij` | `visual-app-editor-intellij-<version>.zip` (`./gradlew buildPlugin`)
| VS Code | `visual-app-editor-vscode` | `visual-app-editor-<version>.vsix` (`pnpm package`)
|===

== Installing from a file (no marketplace)

IntelliJ IDEA / Android Studio::
*Settings | Plugins | ⚙ | Install Plugin from Disk…*, choose the `.zip`, and restart if asked.
The plugin needs platform build 262 or later (IntelliJ IDEA 2026.2+, Android Studio 2026.2+).
Then set the service under *Settings | Tools | Visual App Editor*.

VS Code::
`code --install-extension visual-app-editor-<version>.vsix`, or *Extensions view | ··· | Install from VSIX…*.
Then set `visualAppEditor.serviceCommand` (and optionally `visualAppEditor.reactAdapterCommand`).

Both plugins start the headless service (xref:protocol.adoc[]).
Until compiled `vae_service` executables ship, point them at `dart run <repo>/packages/service/bin/vae_service.dart` after `flutter pub get` in a checkout.

== JetBrains Marketplace

Account and listing::
* A JetBrains Account and a vendor profile (organisation `devcentr`) on https://plugins.jetbrains.com.
* The *first* upload is manual: *Profile | Add new plugin*, then upload the signed zip. Later versions can use `publishPlugin`.
* JetBrains reviews the plugin before it is listed. Follow the Plugin Overview and Plugin UX guidelines:
** an English description of at least 40 characters (`<description>` in `plugin.xml`, already present);
** a vendor URL;
** `<change-notes>` per version (to add);
** a 40×40 `META-INF/pluginIcon.svg`, plus `pluginIcon_dark.svg` (to add, derived from `assets/logo-glyph.svg`);
** a license (MIT, from the repository root).
* The plugin ID `org.devcentr.visual-app-editor` cannot be changed after the first upload.

Compatibility::
* `sinceBuild = 262`, with `untilBuild` left open. `verifyPlugin` runs in CI against the recommended IDEs and must stay `Compatible`.
* Android Studio support comes from depending only on `com.intellij.modules.platform`. To list it explicitly, also verify against an Android Studio build (`ides { create("AI", "<version>") }`).

Signing (required)::
* Create a signing certificate chain and private key, as described in JetBrains' *Plugin Signing* page.
* Provide them to Gradle through environment-backed properties only: `CERTIFICATE_CHAIN`, `PRIVATE_KEY`, `PRIVATE_KEY_PASSWORD`, wired into `intellijPlatform { signing { ... } }`.
* `signPlugin` runs automatically before `publishPlugin`.

Token::
* Create a Marketplace token under *Profile | My Tokens*.
* Pass it as `ORG_GRADLE_PROJECT_intellijPlatformPublishingToken`, read by `intellijPlatform { publishing { token = providers.gradleProperty("intellijPlatformPublishingToken") } }`.
* Store it as a GitHub Actions secret on a protected environment. Keep a local copy only in a password manager, never in the repository or shell history.

Versions and channels::
* Every upload needs a new version.
* `intellijPlatform.publishing.channels = listOf("beta")` publishes to a separate channel, which users must add as a custom repository.

== VS Code Marketplace

Publisher::
* The publisher exists: https://marketplace.visualstudio.com/publishers/devcentr resolves to publisher name `DevCentr`, publisher GUID 88e7dbc5-4446-4b83-823b-4d0989fa95bf (display name DevCentr, checked 2026-10-20).
* `plugins/vscode/package.json` uses `"publisher": "devcentr"`, and Marketplace publisher IDs match case-insensitively. *Confirm the exact ID* on https://marketplace.visualstudio.com/manage before the first publish. The ID is permanent.
* The extension name and display name must be unique in the Marketplace (`visual-app-editor` / *Visual App Editor*).

Package rules enforced by `vsce`::
* The icon is a PNG of at least 128×128 (`media/icon.png`, 256 px), never an SVG.
* README/CHANGELOG images must use `https` URLs and must not be SVG, except trusted badges.
* At most 30 keywords. `README.md`, `CHANGELOG.md` and `LICENSE` are included (the package script copies the root LICENSE).
* `engines.vscode` (currently `^1.100.0`) must be at least the `@types/vscode` version.
* Versions are `major.minor.patch` only. Use `--pre-release` for previews, with odd minors for pre-release and even for release.
* Dependencies are bundled by esbuild, so packaging uses `--no-dependencies`. Only npm and yarn v1 are supported for dependency packaging.

Authentication: no PATs::
*Global Azure DevOps PATs are retired on 2026-12-01.* Use one of these.

Option A: Microsoft Entra ID (works today, `vsce` ≥ 2.26.1)::
. *Identity.* In Azure, create a *user-assigned managed identity* in a dedicated resource group, and give it the *Reader* role scoped to that resource group. Without it the Marketplace cannot resolve the identity. Record the client ID and tenant ID; they are not secrets.
. *GitHub environment.* Create `vscode-marketplace` under repo *Settings → Environments*, with required reviewers. Add the variables `AZURE_CLIENT_ID` and `AZURE_TENANT_ID` as environment *variables*, not secrets.
. *Federated credential.* On the identity, open *Federated credentials → Add → GitHub Actions deploying Azure resources*, with organisation `dev-centr`, repository `visual-app-editor`, entity *Environment* and name `vscode-marketplace`. The subject is `repo:dev-centr/visual-app-editor:environment:vscode-marketplace`. A `:` inside an environment name must be encoded as `%3A`.
. *Marketplace member ID.* The publisher's *Members* page needs the identity's *Visual Studio profile ID*, which is not its client ID, principal ID or Azure resource ID. Get it once by running, while logged in as the identity (for example a one-off `workflow_dispatch` job after `azure/login`):
+
----
az rest -u https://app.vssps.visualstudio.com/_apis/profile/profiles/me --resource 499b84ac-1321-427f-aa17-267ca6975798
----
+
The `id` field in the JSON is the member ID. `499b84ac-…` is the fixed Azure DevOps resource ID.
. *Add the member.* Go to https://marketplace.visualstudio.com/manage/publishers/devcentr → *Members* → *Add*, enter that ID, and choose the *Contributor* role (Microsoft's docs). Community guides report that *Creator* is enough for publishing.
. *Personal Microsoft accounts:* `--azure-credential` needs a Microsoft Entra ID identity in a tenant. A personal Microsoft account (outlook.com and similar) may have no Entra tenant of its own: `az login` then reports no subscriptions or tenants. Create a free Entra tenant, or use an Azure free account, which brings a tenant. Then add that tenant's user or managed identity to the publisher as above.
. *Azure CLI tenant-selector crash:* if the interactive account/tenant picker in `az login` crashes, turn it off with `az config set core.login_experience_v2=off` and retry `az login --allow-no-subscriptions`, optionally with `--tenant <tenant-id>`.
. *Publish locally* instead: `az login --allow-no-subscriptions` as a user who is a member of the publisher, then `npx @vscode/vsce publish --azure-credential --no-dependencies` in `plugins/vscode`. `vsce` uses the Azure CLI credential.

Example workflow. This is *not* in the repository: create `.github/workflows/publish-vscode.yml` only when releasing. It is manual-only.

[source,yaml]
----
name: Publish VS Code extension
on:
  workflow_dispatch:   # manual only; never on push/tag
permissions:
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    environment: vscode-marketplace          # must match the federated credential subject
    permissions:
      contents: read
      id-token: write                       # lets GitHub mint the OIDC token
    defaults:
      run:
        working-directory: plugins/vscode
    steps:
      - uses: actions/checkout@v7
      - uses: pnpm/action-setup@v6
      - uses: actions/setup-node@v7
        with:
          node-version: 24
      - run: pnpm install --frozen-lockfile
      - run: pnpm test
      - run: pnpm package
      - uses: azure/login@v3
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          allow-no-subscriptions: true
      - run: npx @vscode/vsce publish --azure-credential --packagePath visual-app-editor-*.vsix
----

Common errors:

* `AADSTS70021`: the environment does not match the credential subject.
* `Could not get OIDC token`: `id-token: write` is missing.
* `403`: the identity is not a publisher member, or lacks the Reader role.

Option B: Marketplace trusted publishing (`vsce publish --oidc`), *not usable yet*::
* The `vsce` README documents `--oidc`. It exchanges a GitHub OIDC token (audience `marketplace.visualstudio.com`) for a 15-minute Marketplace token.
* As of 2026-10-12 the Marketplace backend still answers `TrustedPublishingNotSupportedException`, and there is no settings page for the policy yet (microsoft/vsmarketplace#1422).
* Re-check before relying on it.

== Open VSX

Account (done)::
* An eclipse.org account with the *same* GitHub username, logged in at https://open-vsx.org, and the Publisher Agreement signed (Settings → Log in with Eclipse → Show Publisher Agreement).

Namespace::
* The namespace is the `publisher` field: `devcentr`.
* Creating it makes you a *contributor*, not an owner. Create it with `npx ovsx create-namespace devcentr -p <token>`, using a token from Settings → Access Tokens.
* Ownership, which shows extensions as verified, is claimed publicly. Open an issue at https://github.com/EclipseFdn/open-vsx.org/issues.

First publish (token required)::
* `npx ovsx publish visual-app-editor-<version>.vsix -p <token>`.
* Trusted publishing cannot be registered for an extension that has no active version yet.

Trusted publishing (GitHub OIDC), after the first version::
* Prerequisites: you are the namespace *owner* (contributor is not enough), the namespace is verified, the Publisher Agreement is signed, and the extension has at least one active version.
* In https://open-vsx.org go to Settings → Trusted Publishers (`/user-settings/trusted-publishers`) and pick the namespace. Choose GitHub Actions, then enter the owner `dev-centr`, the repository `visual-app-editor`, the workflow *file name* only (for example `publish.yml`), and optionally an environment.
* There is one trusted publisher per extension. A registration is not tied to a branch or tag, so pin an environment to restrict it.
* Workflow: `permissions: { contents: read, id-token: write }`, then `npx ovsx publish <vsix> --trusted-publishing`.
* Remove any `OVSX_PAT` / `--pat`: a token takes precedence over OIDC.
* If every version is deleted, the exchange fails until a version is active again.

== Release checklist (when the first release is approved)

. Bump the version in `plugins/intellij/gradle.properties` and `plugins/vscode/package.json`, and add change notes.
. Add the plugin icons, and screenshots for both listings. Screenshots must come from the running IDEs.
. Run `verifyPlugin` and the VS Code integration test, which run in CI anyway.
. Upload manually the first time: JetBrains web upload, VS Code via `vsce publish --azure-credential` or a web upload of the `.vsix`, Open VSX via `ovsx publish`.
. Announce together with the desktop release. The release news page includes an app screenshot (see the roadmap).
